# Frontend Integration

This guide shows how to use Seamless Auth in a React application using the official SDK.

The frontend layer is intentionally thin. It does not verify credentials or tokens. It reads session state from cookies and exposes it to your components.

---

## What the SDK Provides

The React package exposes a small set of primitives:

- `AuthProvider` to initialize the client
- `useAuth()` to access session state and actions
- Optional helpers for common UI flows

All security-sensitive work happens on the auth server and in your API.

---

## Installation

```bash
npm install @seamless-auth/react react-router-dom
```

TypeScript types are included.

---

## AuthProvider

Wrap your application with `AuthProvider`.

```tsx
import { BrowserRouter } from 'react-router-dom'
import { AuthProvider } from '@seamless-auth/react'
import App from './App'

export default function Root() {
  return (
    <BrowserRouter>
      <AuthProvider apiHost={import.meta.env.VITE_API_URL} mode="server">
        <App />
      </AuthProvider>
    </BrowserRouter>
  )
}
```

Key options:

- `apiHost` points to your API
- `mode` controls how requests are made (`server` routes through your API)

What the provider does:

- reads and syncs cookies with the backend
- fetches current session state
- exposes auth state to the component tree

## useAuth Hook

Use `useAuth()` anywhere in your component tree.

```tsx
import { useAuth } from '@seamless-auth/react'

const { user, isAuthenticated, login, register, logout, hasRole } = useAuth()
```

Common fields:

- `user` → current user or `null`
- `isAuthenticated` → boolean
- `login()` → start verification flow
- `register()` → create a new credential
- `logout()` → clear session
- `hasRole(role)` → check authorization hints in the UI

The `user` object is derived from server-verified state.

---

## Starting Authentication

Call `login()` to begin a sign-in flow.

```tsx
const { login } = useAuth()

<button onClick={() => login({ email: 'user@example.com' })}>
  Sign in
</button>
```

Or call `register()` to create a new credential.

```tsx
const { register } = useAuth()

<button onClick={() => register({ email: 'user@example.com' })}>
  Register
</button>
```

The SDK sends requests to your API. The API forwards them to the auth server. The frontend never handles secrets.

---

## Session State

After verification succeeds:

- the auth server sets HTTP-only cookies
- the browser stores them automatically
- the SDK reads session state via your API

You do not store tokens in localStorage or attach headers manually.

---

## Rendering Based on Auth State

Use `isAuthenticated` or `user` to control UI.

```tsx
const { isAuthenticated, user } = useAuth()

if (!isAuthenticated) {
  return <SignIn />
}

return <Dashboard user={user} />
```

Keep authorization decisions in your API. The frontend should only reflect state.

---

## Logging Out

```tsx
const { logout } = useAuth()

<button onClick={logout}>Sign out</button>
```

This clears cookies and resets local state.

---

## Routing Patterns

A simple protected route pattern:

```tsx
import { useAuth } from '@seamless-auth/react'
import { Navigate } from 'react-router-dom'

function Protected({ children }: { children: React.ReactNode }) {
  const { isAuthenticated } = useAuth()

  if (!isAuthenticated) {
    return <Navigate to="/login" replace />
  }

  return <>{children}</>
}
```

Use this to guard routes in your router.

---

## How Requests Flow

With `mode="server"`:

1. The browser calls your API
2. Cookies are included automatically
3. The API validates the session
4. The API responds with data

The frontend never talks directly to the auth server in this mode.

---

## Development Notes

- The SDK assumes cookies are available on `localhost`
- No client-side token storage is required
- Network requests are simple `fetch` calls to your API

If something fails, check the API and auth server logs rather than the browser first.
