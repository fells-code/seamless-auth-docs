# Seamless Auth CLI

The Seamless Auth CLI (`create-seamless`, also available as `seamless`) is the entry point for
scaffolding and checking a local Seamless Auth project.

Current public commands focus on:

- Scaffold applications
- Validate the generated project
- Bootstrap the first admin user

---

## Mental Model

```
CLI -> Generates App -> Wires Local Stack -> Helps You Operate It
```

---

## Installation

No global install required. Use via npx:

```bash
npx create-seamless
```

---

## Core Commands

### init (default)

```bash
npx create-seamless init my-app
```

Or simply:

```bash
npx create-seamless my-app
```

Creates a new Seamless Auth project.

---

### check

```bash
npx create-seamless check
```

Validates local project setup, Docker availability, and running services.

---

### bootstrap-admin

```bash
npx create-seamless bootstrap-admin admin@example.com
```

Creates a bootstrap admin invite for the first admin user.

The CLI will try to resolve the bootstrap secret from local project files before prompting you for
it manually.

---

## CLI Behavior

If no command is provided:

- CLI defaults to `init`
- Uses current directory if empty
- Prompts for project name otherwise

---

## Help Menu

```bash
npx create-seamless --help
```

Displays:

- Available commands
- Usage patterns
- Flags and options

---

## What Happens During init

The CLI will:

1. Ask configuration questions
2. Generate the web and API starters
3. Configure the auth server in Docker or local mode
4. Optionally include the admin dashboard
5. Generate Docker Compose and local config

---

## Generated Files

```txt
web/
api/
auth/                  # only in local auth mode
admin/                 # only in admin source mode
docker-compose.yml
seamless.config.json
README.md
```

---

## Design Philosophy

The CLI is built to be:

- **Opinionated** → best practices by default
- **Guided** → interactive prompts
- **Focused** → local scaffolding and setup checks today

---

## What It Does Not Do Yet

The current public CLI does **not** expose a production deployment command.

It also does not yet provide a polished “attach Seamless Auth to an existing application” workflow.

If you see older docs or notes mentioning `deploy`, treat that as planned or in-progress work, not
as part of the current public command set.
