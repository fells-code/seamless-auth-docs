# Deployment Status

Deployment support is an area of active development, but it is important to separate the current
state from the intended future workflow.

---

## Current State

The current public `create-seamless` CLI focuses on:

- `init`
- `check`
- `bootstrap-admin`

There is **not** currently a public `deploy` command in the CLI.

---

## What Exists Today

Today, Seamless Auth supports:

- Local scaffolding
- Self-hosting the auth API
- Running the admin dashboard separately
- Building applications on top of the server and frontend SDKs

Production deployment is still something you should plan explicitly in your own infrastructure
workflow.

---

## Intended Direction

The long-term direction is a guided deployment story that can take a locally working stack toward a
repeatable production environment.

That is also the point where this docs area should expand again in a major way, alongside better
guides for integrating Seamless Auth into an existing application instead of only a newly scaffolded
one.

---

## Documentation Rule

If you are documenting deployment work:

- label planned behavior clearly
- do not present a future CLI command as already shipped
- tie infrastructure claims to a source repo or implementation artifact

This is especially important for agents and operators who may treat docs as source of truth.
