# Getting Started

This guide walks through setting up Seamless Auth for local development. It focuses on understanding the system, running it end to end, and integrating it into your application.

There are two supported paths:

- **Quick start** using the [`create-seamless`](https://github.com/fells-code/create-seamless) CLI (recommended)
- **Manual integration** into an existing application

Both approaches use the same architecture and authentication model.

---

## Prerequisites

You should be comfortable with:

- JavaScript or TypeScript
- Running Node.js applications
- Using npm or pnpm
- Basic familiarity with HTTP and cookies

No prior experience with OAuth, OpenID Connect, or identity providers is required.

---

## Option 1: Quick Start (Recommended)

The fastest way to get a working Seamless Auth environment is with the official CLI.

```bash
npx create-seamless my-app
cd my-app
```

By default, this generates:

- Seamless Auth server
- Express API example
- React (Vite) web application
- Optional Docker Compose configuration

---

### Running with Docker (one command)

If you have Docker installed, you can start the entire stack with:

```bash
docker compose up
```

This will start:

- Postgres database
- Seamless Auth server
- API server
- Web UI

Once running, open:

```
http://localhost:5173
```

All services run in development mode with hot reload enabled.

---

### Running services manually

If you prefer not to use Docker, you can run each service directly.

In separate terminals:

```bash
cd auth && npm install && npm run dev
```

```bash
cd api && npm install && npm run dev
```

```bash
cd web && npm install && npm run dev
```

This approach is useful when debugging or modifying individual services.

## Option 2: Integrating into an Existing React App

You can also integrate Seamless Auth into an existing React application.

### Install dependencies

```bash
npm install @seamless-auth/react react-router-dom
```

---

### Wrap your application with `AuthProvider`

In your application entry point:

```tsx
import { BrowserRouter } from 'react-router-dom'
import { AuthProvider } from '@seamless-auth/react'
import App from './App'

export default function Root() {
  return (
    <BrowserRouter>
      <AuthProvider apiHost={import.meta.env.VITE_AUTH_SERVER_URL} mode="server">
        <App />
      </AuthProvider>
    </BrowserRouter>
  )
}
```

The `AuthProvider` initializes authentication, manages cookies, and exposes session state to your application.

---

## Using Authentication State

Authentication state is accessed via the `useAuth()` hook.

```tsx
import { useAuth } from '@seamless-auth/react'

const { user, isAuthenticated, logout, hasRole } = useAuth()
```

Common properties:

- `user` – the authenticated user object or `null`
- `isAuthenticated` – whether the current session is authenticated
- `logout()` – clears the session
- `hasRole(role)` – checks role membership

---

## Routing and Protected Views

Seamless Auth does not require special routing primitives. Instead, authentication state is used directly in your components.

Example:

```tsx
function Home() {
  const { isAuthenticated } = useAuth()

  if (!isAuthenticated) {
    return <SignIn />
  }

  return <Dashboard />
}
```

This keeps routing explicit and easy to reason about.

---

## Development Behavior

In development:

- OTPs may be logged to the console
- Cookies are issued locally
- No external email or SMS providers are required

Production deployments use the same authentication model with real delivery providers.
