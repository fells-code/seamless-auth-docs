# Getting Started

This guide walks you through setting up **SeamlessAuth** for the first time.  
We’ll cover two approaches — using the CLI quick-start (`npx create-seamless`) or adding SeamlessAuth directly to an existing React project.

---

## Before You Begin

We assume you’re already comfortable with:

- Basic **JavaScript/TypeScript** syntax.
- Working in a **React** environment.
- Using **npm** or **yarn** for package installation.
- Familiarity with React Router (for client-side routing).

If you already have those skills — you’re ready to go. 🚀

---

## Option 1: Quick Start with `npx create-seamless`

The easiest way to get started is using our official CLI.  
This creates a fully configured example project with all SeamlessAuth components and routing built in.

```bash
npx create-seamless my-app
cd my-app
npm install
npm run dev
```

You’ll get:

- A working React app using **Vite + TypeScript**
- Preconfigured `AuthProvider`
- Protected routes and sign-in flow
- SeamlessAuth environment configuration

> **Pro tip:** You can pass flags to skip prompts or select specific modes (like `--server` or `--web`):
>
> ```bash
> npx create-seamless my-app --web
> ```

---

## Option 2: Install Manually in an Existing React App

Already have a React app? You can integrate SeamlessAuth in just a few steps.

### 1️⃣ Install dependencies

```bash
npm install @seamless-auth/react react-router-dom
```

If you’re using TypeScript, you might also want the router types:

```bash
npm install -D @types/react-router-dom
```

### 2️⃣ Wrap your App with `AuthProvider`

In your main entry file (`main.tsx` or `index.tsx`):

```tsx
import React from 'react'
import { createRoot } from 'react-dom/client'
import { BrowserRouter } from 'react-router-dom'
import { AuthProvider } from '@seamless-auth/react'
import App from './App'

createRoot(document.getElementById('root')!).render(
  <React.StrictMode>
    <BrowserRouter>
      <AuthProvider apiHost={import.meta.env.VITE_API_HOST}>
        <App />
      </AuthProvider>
    </BrowserRouter>
  </React.StrictMode>,
)
```

The `AuthProvider` automatically initializes SeamlessAuth, synchronizes user sessions via secure cookies, and exposes auth context throughout your app.

---

## Understanding the Auth Context

The `AuthProvider` makes a React context available everywhere in your app via the `useAuth()` hook.

You can access common properties like:

```tsx
const { user, isAuthenticated, logout, hasRole } = useAuth()
```

| Property                | Type                | Description                           |
| ----------------------- | ------------------- | ------------------------------------- |
| `user`                  | `User \| null`      | The authenticated user object         |
| `isAuthenticated`       | `boolean`           | True when the user is signed in       |
| `logout()`              | `() => void`        | Clears cookies and signs out the user |
| `hasRole(role: string)` | `(role) => boolean` | Checks if user has a specific role    |

Example usage:

```tsx
import { useAuth } from '@seamless-auth/react'

function Dashboard() {
  const { user, isAuthenticated, logout } = useAuth()

  if (!isAuthenticated) {
    return <div>Please sign in to continue</div>
  }

  return (
    <div>
      <h1>Welcome {user?.email}</h1>
      <button onClick={logout}>Log out</button>
    </div>
  )
}
```

## Auth Routes

SeamlessAuth provides built-in **`AuthRoutes`** that automatically handle protected and public routes using React Router.

### Example

```tsx
import { AuthRoutes } from '@seamless-auth/react'
import Home from './pages/Home'
import Dashboard from './pages/Dashboard'

export default function App() {
  return (
    <AuthRoutes>
      <Route path="/" element={<Home />} />
      <Route path="/dashboard" element={<Dashboard />} auth="protected" />
    </AuthRoutes>
  )
}
```

| Attribute           | Description                                                                     |
| ------------------- | ------------------------------------------------------------------------------- |
| `auth="protected"`  | Restricts access to authenticated users. Redirects to sign-in if not logged in. |
| `auth="public"`     | Always accessible (default).                                                    |
| `auth="guest-only"` | Redirects _away_ if already signed in (useful for sign-in or register pages).   |

## Adding Sign-In and Sign-Out

By default, SeamlessAuth gives you two helper methods via `useAuth()`:

```tsx
const { login, logout } = useAuth()
```

Example sign-in component:

```tsx
function SignIn() {
  const { login } = useAuth()
  return (
    <button onClick={() => login({ email: 'user@example.com' })} className="btn-primary">
      Sign In with Passkey
    </button>
  )
}
```

> The `login()` method triggers SeamlessAuth’s passwordless flow — using WebAuthn and Passkeys under the hood.

## Development Environment

In development, you can use your SeamlessAuth sandbox environment (`localhost:5001` by default) for testing.

If your setup includes API Gateway restrictions, make sure to add your local host in the allowed origins list (e.g., `http://localhost:5173`).

```env
VITE_API_HOST=http://localhost:5001
```

Then restart your dev server to apply it.
