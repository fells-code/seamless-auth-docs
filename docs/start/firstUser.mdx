## Register Your First User

This guide walks you through completing your first authentication flow using SeamlessAuth.

By the end, you will:

- Create a user
- Complete a passwordless login
- Establish a session
- See authenticated state in your application

---

## What You Should Have Ready

Before starting:

- Your app is running locally
- Docker services are running
- You can access [http://localhost:5173](http://localhost:5173)

---

## Step 1: Open the App

Navigate to:

```
http://localhost:5173
```

You should see the SeamlessAuth starter UI.

<Image
  src="/uiStarterTemplate.png"
  alt="SeamlessAuth Starter UI"
  caption="SeamlessAuth starter UI"
/>

---

## Step 2: Enter Your Email

In the registration form:

- Enter an email address (eg. test001@test.com)
- Enter your phone number (eg. +14109850001)
- Submit the form

SeamlessAuth will:

- Detect that the user does not exist
- Automatically begin the registration flow

---

## Step 3: Receive OTPs

After providing a test email and phone number you will receive:

- A one-time password (OTP) for phone verification first

In development mode, this will be:

- Logged in the console

<Image src="/otp.png" alt="OTP example in terminal" caption="OTPs are logged out in the console" />

---

## Step 4: Verify OTPs and create your first Passkey

- Complete the OTP prompts

Once verified:

- A user record is created
- Passkey registration is prompted
- A session is issued

<Image
  src="/passkeyReg.png"
  alt="Passkey registration screen"
  caption="SeamlessAuth uses webauthn as it's core for passkeys"
/>

---

## Step 5: Session Established

After verification:

- A secure HTTP-only cookie is set
- Your frontend SDK detects the session
- The UI updates to an authenticated state

<Image
  src="/loggedIn.png"
  alt="SeamlessAuth Starter UI - logged in landing page"
  caption="SeamlessAuth starter UI logged in screen"
/>

---

## What Just Happened

Behind the scenes:

1. Your frontend called your API server
2. The API server proxied the request for authentication to the auth server
3. A verification challenge was issued
4. You completed verification
5. A session was created
6. A secure cookie was set
7. The SDK updated your application state
8. All subsquent requests are sent through an auth check endpoint before touching any of your business logic

<Card title="Key Concept">
  Authentication and registration are passwordless and naturally deconflicting. A user is created
  automatically during their first successful verification and can normally deconflict any account
  issues via the registration process.
</Card>
