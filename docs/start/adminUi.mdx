## Admin UI

The SeamlessAuth Admin UI provides a centralized interface for managing your authentication system.

It is designed for **operational visibility and control**, allowing you to inspect users, sessions, and security events in real time.

---

## Access Requirements

Only users with the `admin` role can access the Admin UI.

If a non-admin attempts access:

- They will be denied access
- Or redirected depending on your configuration

<Callout type="info">
  The Admin UI is backed entirely by the same API you control. There is no hidden logic—everything
  maps directly to your system.
</Callout>

---

## Overview of Interfaces

The Admin UI consists of six primary sections:

<Card title="Admin UI Sections">
  - Dashboard (Metrics & Overview) - Users - Sessions - Events (Audit Logs) - Security - System
  Configuration
</Card>

---

## Dashboard

The dashboard provides a high-level view of your system.

It includes:

- User counts
- Session activity
- Authentication trends
- System health indicators

This page helps you quickly answer:

- Is my system active?
- Are users logging in successfully?
- Is anything unusual happening?

<Image src="/adminPortal.png" alt="Seamless Admin portal" caption="Admin portal dashboard" />

---

## Users

The Users page is the primary interface for managing identities.

You can:

- View all users
- Edit user details
- Assign or remove roles
- Revoke sessions
- Disable (revoke) users entirely

<Callout type="tip">
  Revoking a user will prevent future authentication and should be used for compromised or invalid
  accounts.
</Callout>

<Image src="/adminUsers.png" alt="Seamless Admin users view" caption="Admin portal users" />

---

## Sessions

The Sessions page shows all active sessions across users.

Each session represents a device or browser instance.

You can:

- View active sessions
- Inspect device and IP information
- Revoke individual sessions

This enables:

- Device-level security
- Debugging login issues
- Supporting users across devices

## Events (Audit Logs)

The Events page provides a detailed audit trail of authentication activity.

Examples include:

- user_created
- registration_success
- verify_otp_success
- webauthn_registration_success

You can use this to:

- Debug authentication flows
- Track user behavior
- Audit system activity

## Security

The Security section highlights suspicious or noteworthy activity.

This may include:

- Repeated failed logins
- Unusual IP behavior
- Rapid session creation

This helps you:

- Detect potential abuse
- Investigate anomalies
- Improve system safety

<Image
  src="/adminSecurity.png"
  alt="Seamless Admin security view"
  caption="Admin portal security"
/>

## System Configuration

The System page allows you to manage runtime configuration.

You can update:

- Token TTLs (access / refresh)
- Available roles
- Default roles
- Application metadata

These settings are stored in your system config and applied dynamically.

<Callout type="warning">
  Changes to system configuration can impact authentication behavior. Apply updates carefully and
  validate in development first.
</Callout>

## How It All Connects

Each section of the Admin UI maps directly to core data models:

- Users → `users`
- Sessions → `sessions`
- Events → `auth_events`
- System → `system_config`

This ensures:

- Full transparency
- Predictable behavior
- No hidden state

---

## What This Enables

With the Admin UI, you can:

- Operate your auth system without direct database access
- Debug issues quickly
- Manage users and sessions safely
- Monitor security and activity

<Card title="Key Concept">
  The Admin UI is an operational layer, not a control layer. It surfaces your system—it does not
  replace your application logic.
</Card>
