## Managed Quickstart

This guide takes you from signing up on the Seamless Auth portal to a real app where a user can sign
in, using a hosted auth instance that Seamless runs for you. You do not run a database, signing keys,
or an auth server on this path.

If you would rather run the whole stack yourself, follow the
[Self-Hosted Quickstart](/start/quickstart) instead. Not sure which path fits? See
[Managed or Self-Hosted](/start/choose-your-path).

---

## What you will need

- Node 22 or newer and a package manager (`npm` is used below)
- An existing app, or two empty projects: a React frontend and an Express backend
- A web browser and an email inbox you control
- About ten minutes

<Aside type="note">
  You do not need Docker, Postgres, or the CLI for the managed path. Those are for self-hosting.
</Aside>

---

## Step 1: Sign up to the portal

Open the Seamless Auth portal at
[https://dashboard.seamlessauth.com](https://dashboard.seamlessauth.com) and sign up.

The portal is itself passwordless and built on Seamless Auth, so there is no password to choose:

1. Enter your email on the sign-up screen.
2. Open the verification code sent to your inbox and enter it.
3. Register a passkey when prompted, or continue with email and magic links.

You now have a portal account. The portal is where you create applications, manage plans and billing,
generate service tokens, and review logs and auth events for each application. End users and roles
live in the admin console bundled with each instance, which the portal links to.

---

## Step 2: Create an application

An application is one hosted auth instance. From the dashboard, choose **Create your first
application** (or **New Application**) and fill in the form.

**Basic fields:**

- **App Name** (3 to 32 characters, letters, numbers, and single spaces)
- **Frontend URL** (your app's origin, must be `https://...`)
- **Service Plan** (see the plans below)

**Advanced fields** are optional and have safe defaults. They include notification email(s),
application roles and default role, a development-mode toggle, AWS region, access and refresh token
TTLs, and rate-limit thresholds.

### Plans

| Plan       | Price      | Notes                                             |
| ---------- | ---------- | ------------------------------------------------- |
| Trial      | Free       | 14 days on MVP or Business, card required         |
| MVP        | $49 / mo   |                                                   |
| Business   | $149 / mo  | Recommended for most new products                 |
| Enterprise | Contact sales | Not self-serve, email support@fellscode.com |

<Aside type="tip">
  A trial runs the plan you pick (MVP or Business) free for 14 days, then converts to that plan.
  Starting one takes a card through Stripe checkout, and each card gets one trial. If the first charge
  fails when the trial ends, the instance is removed.
</Aside>

For a paid plan or a trial, the portal sends you through Stripe checkout before provisioning.

### Provisioning

After you submit, Seamless provisions the instance. This takes a few minutes (the portal estimates
about five). When it finishes, the application has its own **Auth Server URL**. This URL is what
your backend adapter points at (your frontend points at your backend).

Copy it from the application's **Credentials** page, in the **Auth API Configuration** card, rather
than building it by hand. The host depends on the plan:

| Plan       | Auth Server URL                              |
| ---------- | -------------------------------------------- |
| Trial      | `https://<infra-id>.trials.seamlessauth.com` |
| Paid plans | `https://<infra-id>.seamlessauth.com`        |

`<infra-id>` is an identifier the portal assigns when it provisions the instance, not your
application name. Upgrading a trial moves the instance to the paid host, so copy the URL again after
an upgrade.

## Step 3: Get a service token

Your backend authenticates to the hosted auth instance with a **service token**. Generate it from the
application's **Auth API Configuration** card:

1. Open your application in the portal and choose **Credentials** in the sidebar.
2. Find the **Auth API Configuration** card and its **Service Token** section.
3. Choose **Generate Token**.

The full token is shown **once**. Copy it immediately and store it as a server-side secret. The portal
keeps only a masked copy (the last few characters) for reference, so it cannot show you the full value
again.

<Aside type="caution">
  Treat the service token like a password. Keep it in a server-side environment variable, never in
  frontend code, and never commit it. If it leaks, use **Rotate Token** on the same card. Rotating
  invalidates the previous token immediately.
</Aside>

The service token is a long, URL-safe secret. Your backend reads it from an environment variable
(shown as `SEAMLESS_SERVICE_TOKEN` below); the frontend never sees it.

## Step 4: Connect your backend

Your backend runs the Seamless Auth adapter. It is the only piece that talks to the hosted instance:
it holds the service token, sets the session cookies in the browser, and calls the Auth Server URL
over bearer tokens. The browser never talks to the Auth Server URL directly.

Install the Express adapter and CORS middleware in your backend project:

```bash
npm install @seamless-auth/express cors
```

Mount the adapter at `/auth`. Point `authServerUrl` and `audience` at your **Auth Server URL**, read
from `AUTH_SERVER_URL`:

```ts
import cors from 'cors';
import express from 'express';
import createSeamlessAuthServer from '@seamless-auth/express';

const app = express();

// The browser SDK sends cookies, so the frontend origin must be allowed with credentials.
app.use(cors({ origin: process.env.FRONTEND_ORIGIN, credentials: true }));

app.use(
  '/auth',
  createSeamlessAuthServer({
    authServerUrl: process.env.AUTH_SERVER_URL!,
    audience: process.env.AUTH_SERVER_URL!,
    cookieSecret: process.env.COOKIE_SIGNING_KEY!,
    serviceSecret: process.env.SEAMLESS_SERVICE_TOKEN!, // from the portal, shown once
    jwksKid: process.env.JWKS_KID!,
  }),
);

app.listen(3000);
```

Set these environment variables on your backend:

| Variable                 | Value                                                                                                |
| ------------------------ | ---------------------------------------------------------------------------------------------------- |
| `AUTH_SERVER_URL`        | Your Auth Server URL, copied from Credentials → Auth API Configuration                               |
| `SEAMLESS_SERVICE_TOKEN` | The service token generated in Step 3                                                                |
| `COOKIE_SIGNING_KEY`     | A random secret of at least 32 characters, for example from `openssl rand -base64 48`                |
| `JWKS_KID`               | `kid` header on the service tokens your adapter signs; the auth API does not check it, and `seamless init` writes your instance's active key id from `/.well-known/jwks.json` |
| `FRONTEND_ORIGIN`        | Your frontend's origin, for example `http://localhost:5173`                                          |

The service token is never sent raw. The adapter uses it to sign short-lived service tokens for
machine-to-machine calls to your hosted instance. To protect routes, add `requireAuth` and
`requireRole` from the same package. See the [Server SDKs](/build/server-sdks) reference for the full
option list and middleware.

## Step 5: Connect your frontend

Install the React SDK in your frontend project:

```bash
npm install @seamless-auth/react
```

Wrap your app in `AuthProvider`, using **your backend's origin** as `apiHost`, then read session state
with `useAuth()`. The SDK calls the adapter you mounted at `/auth` on that origin.

```tsx
import { AuthProvider, useAuth } from '@seamless-auth/react';

const API_URL = 'http://localhost:3000';

export function App() {
  return (
    <AuthProvider apiHost={API_URL}>
      <AppRoutes />
    </AuthProvider>
  );
}

function AppRoutes() {
  const { isAuthenticated, user } = useAuth();

  return isAuthenticated ? <p>Signed in as {user?.email}</p> : <LoginPage />;
}
```

<Aside type="caution">
  Do not set `apiHost` to the Auth Server URL. The hosted instance speaks bearer tokens to your
  backend and sets no browser cookies, so a browser pointed at it cannot sign in.
</Aside>

`AuthProvider` needs only `apiHost`; its other props are optional. There is no frontend token or
client id: the browser SDK carries no secret and relies on the cookies your backend sets. For
built-in sign-in screens, mount `AuthRoutes` from `@seamless-auth/react/routes`; for custom UI, use
the headless client. See the [React SDK](/build/react-sdk) reference for the full API.

<Aside type="tip">
  Put the backend origin in a frontend environment variable (for example `VITE_API_URL` in a Vite
  app) rather than hardcoding it, so the value differs cleanly between environments.
</Aside>

<Aside type="note">
  The portal shows these same install commands and snippets in its built-in **Get connected** wizard,
  with your Auth Server URL already filled in. This guide mirrors that wizard so you can follow either
  one.
</Aside>

## Step 6: Test a login

Run your frontend and backend, then sign in:

1. Open your app and start the sign-in flow.
2. Sign in with a passkey or an emailed code.
3. Confirm the session resolves and `useAuth()` reports the user as authenticated.

Back in the portal, the application's **Logs** page records the sign-in on its **Auth events** tab,
and the **Users** count on the application **Dashboard** includes the new account.

To manage that user, choose **Open admin console** on the application **Dashboard**. It opens the
admin console bundled with your instance (at `/console` on your instance URL). Its **Users** screen
lists end users (open one to edit its roles), its **Events** screen shows the auth event stream, and
its **System** screen defines the available and default roles. See
[Explore the Admin Dashboard](/start/adminui) for a tour.

## Where things live in the portal

| You need to                     | Go to                                                       |
| ------------------------------- | ----------------------------------------------------------- |
| Copy your Auth Server URL       | Credentials → Auth API Configuration                        |
| Generate or rotate the token    | Credentials → Auth API Configuration → Service Token        |
| See sign-ins and auth events    | Logs → Auth events tab                                      |
| Manage end users and roles      | Dashboard → **Open admin console** → Users                  |
| Change or upgrade your plan     | Billing → Change plan                                       |
| Re-run the connection steps     | Dashboard → Get connected (Connection guide once completed) |
