## Self-Hosted Quickstart

Scaffold the recommended local stack with no prompts (safe in CI, scripts, and agents, since it
never waits for input):

```bash
npx seamless-cli init my-app --local --yes --email=you@example.com
cd my-app
docker compose up
```

`--local` scaffolds a self-hosted stack, `--yes` takes the recommended answer for every remaining
question, and `--email` sets the owner address that becomes the first admin when you register with
it. The result is a React web app, an Express API, the auth server as a Docker image, and the admin
console served by the API at `/console`. The full flag list is in the
[CLI Command Reference](/reference/cli-commands).

This guide walks through the fastest supported way to run Seamless Auth yourself: scaffold a
project with the CLI, start the stack locally, and sign in as the first admin. The steps below use
the interactive form so you can see each choice.

<Aside type="tip">
  Want authentication working without running a database or an auth server? Use the
  [Managed Quickstart](/start/managed-quickstart) instead, where Seamless hosts the auth instance for
  you. See [Managed or Self-Hosted](/start/choose-your-path) to compare.
</Aside>

## What you will need to complete this walkthrough

- Node 22 or newer (the CLI's supported range is `>=22`)
- Docker with Docker Compose, which runs Postgres and every other service for you
- A terminal
- A web browser

<Aside type="note">
  We utilize docker and docker compose for the entire demonstration. For best follow along
  experience we encourage you to do the same.
</Aside>

## What is the CLI?

The Seamless Auth CLI is published as `seamless-cli` and exposes the `seamless` binary. It
scaffolds a working local project around the auth ecosystem.

Today it is primarily used to:

- Scaffold the web app and API starter
- Configure the auth server in Docker or local mode
- Optionally include the admin dashboard
- Generate local secrets and service-to-service wiring
- Validate the generated local stack
- Make the email you give it the first admin

<Aside type="note">
  The current CLI is opinionated on purpose. It prefers giving you a working local stack over
  exposing every possible architecture choice up front.
</Aside>

## CLI Help Menu

Before starting, you can inspect available commands:

```bash
npx seamless-cli --help
```

This will show:

- Every command (`init`, `templates`, `check`, `verify`, and the instance commands such as
  `users` and `config`)
- Usage patterns

Every command also documents itself, for example `npx seamless-cli init --help`.

---

## Step 1: Initialize a Project

Run the CLI:

```bash
npx seamless-cli init my-app
cd my-app
```

Scaffolding always goes through `init`. A bare project name (`npx seamless-cli my-app`) is rejected
as an unknown command, and running the CLI with no command prints help.

---

## Step 2: Interactive Setup

The CLI will guide you through:

- The web starter
- The backend framework
- Whether to include a mobile starter
- **Your email address.** It becomes the owner, and registering with it later makes you the first
  admin
- How to run the auth server (Docker or local)
- Where the admin console is hosted (served by your API at `/console`, a separate container, or
  not at all)

<Aside type="tip">
  Choose Docker mode for the most reliable local environment. It closely mirrors production
  behavior.
</Aside>

## Step 3: Generated Project Structure

After setup, your project will look like:

```txt
my-app/
  web/
  api/
  auth/                  # only when local auth mode is selected
  admin/                 # only when admin source mode is selected
  docker-compose.yml
  seamless.config.json
```

The exact shape depends on the options you selected, but the CLI always wires the generated pieces
together for local development.

---

## Step 4: Start with Docker (Recommended)

The CLI generates a Docker-based development environment.

Start services:

```bash
docker compose up
```

This will:

- Start Postgres
- Start the Seamless Auth server
- Start a template web application
- Start a template API server
- Start the admin dashboard if you included it
- Use the generated local config and service tokens

## Step 6: Register As The First Admin

There is no separate admin command. `init` wrote the email you gave it to the auth server as
`OWNER_EMAIL`, and the auth server grants the admin role to the account created with that address.

1. In the web app at `http://localhost:5173`, register with the email you gave `init`.
2. When asked for a code, read it from the API logs. In local development the starter API logs
   codes instead of sending email:

   ```bash
   docker compose logs -f api
   ```

   Look for a line like `Dev OTP for you@example.com: 123456`.
3. Enter the code, and enroll a passkey when prompted.

You are now signed in as an admin. Open the admin console at `http://localhost:3000/console` (or
`http://localhost:5174` if you chose a separate dashboard container).

<Aside type="caution">
  The grant happens only when the account is created. Changing `OWNER_EMAIL` after that account
  exists promotes nobody.
</Aside>
