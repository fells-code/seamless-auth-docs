## Create Your First Admin

The first admin of a local stack is whoever registers with the owner email you gave `seamless init`.
There is no invite to create and no admin command to run.

---

## Before You Start

Make sure:

- your local stack is running (`docker compose up`)
- you can access the web app at `http://localhost:5173`
- you know the email you entered for the owner during `init`

---

## How The Owner Grant Works

`init` writes your email to the auth server as `OWNER_EMAIL`. When an account is created with an
address on that list, the auth server grants it the `admin:write` and `admin` roles.

The grant is safe because both signup paths prove control of the address before the account
exists: email OTP verification, or a verified profile from an OAuth provider.

<Aside type="caution">
  The grant happens only at account creation. Changing `OWNER_EMAIL` after that account exists
  promotes nobody. To make someone else the owner, set their address in `auth/.env` (or the compose
  file) before they register. `OWNER_EMAIL` also accepts a comma separated list.
</Aside>

After the first admin exists, grant admin to other people from the admin console or with
`seamless users`, not through `OWNER_EMAIL`.

---

## Step 1: Register With The Owner Email

Open `http://localhost:5173` and register with the same email you gave `init`.

---

## Step 2: Enter The Code

In local development the starter API logs one-time codes instead of sending email. Read the code
from its logs:

```bash
docker compose logs -f api
```

Look for a line like `Dev OTP for admin@example.com: 123456`, enter the code, and enroll a passkey
when prompted.

---

## Step 3: Verify The Role

After registration, the session's roles include `admin:write` and `admin` alongside the instance's
default roles (set by `DEFAULT_ROLES`):

```json
{
  "roles": ["<default roles>", "admin:write", "admin"]
}
```

## Step 4: Open The Dashboard

Navigate to the admin console. By default your API serves it at:

```txt
http://localhost:3000/console
```

If you chose a separate dashboard container during `init`, it is at `http://localhost:5174`
instead.

<Image src="/adminOverview.png" alt="Seamless Admin portal" caption="Admin dashboard overview" />

---

## What Just Happened

- `init` recorded your email as the owner
- registration with that email verified you controlled it
- the new account received the admin roles at creation
- the admin console became accessible through normal auth state
